# PAFシステムの構成方針

更新日：2026-11-20（JST）

## 目的と進め方

現行の研究結果を再現できる構成を、利用者と対話しながら段階的に作る。直接実行するスクリプトを一か所に集め、システム共通部品、学習処理、推論処理を区別する。各段階の動作と配置を確認してから次へ進み、すべての実験を一度に移植しない。

現行構成と研究結果の参照先は[システム構成資料](../SYSTEM_MAP.md)。以下は新構成の設計であり、実装済みの機能一覧ではない。

## 配置

|場所|役割|利用者の操作|
|---|---|---|
|`scripts/train.py`|学習の実行入口|直接実行する|
|`scripts/predict.py`|画像を指定して推論する入口|直接実行する|
|`scripts/evaluate.py`|固定評価データの性能測定の入口|直接実行する|
|`scripts/report.py`|保存した評価結果の集計・図生成の入口|直接実行する|
|`configs/`|学習・推論・評価条件とデータ・モデルの場所|必要な条件を編集する|
|`src/paf/core/`|CNN、画像前処理、楕円・点群処理、入出力の共通部品|手法自体を変更するときに編集する|
|`src/paf/training/`|dataset、教師・損失、拡張、学習ループ|学習方法を変更するときに編集する|
|`src/paf/inference/`|重み読込、境界推定、楕円化、出力|推論方法を変更するときに編集する|
|`src/paf/evaluation/`|評価用入力、幾何比較器との接続、IoU、集計|評価方法を変更するときに編集する|
|`tests/`|必要な動作確認と既存結果との一致確認|通常はテスト実行時のみ使う|
|`docs/`|構成・操作・現在の仕様と未検証事項|参照する|

学習用と推論用の入口は、同じ`scripts/`にある別ファイルとする。入口には引数・設定の読込と呼出しだけを置き、長い実装を埋め込まない。必要な入口だけを各段階で作り、未実装のダミースクリプトは置かない。

データ・モデル・生成結果は役割を分ける。物理的な保存先は設定から指定し、旧実験名を本体コードへ埋め込まない。既存の大きな画像集合・重みを最初から複製または移動せず、必要なものの参照先を明示する。

## 依存関係の規則

- `scripts/`は`src/paf/`の機能を呼ぶ。`src/paf/`から`scripts/`を読み込まない。
- 学習と推論は`core`を共有する。推論から学習ループ・学習用datasetを読み込まない。
- 新しい本体は`research/`と`paf_ring_detection/`をimportしない。必要な処理を役割ごとに移植し、旧コードを呼ぶだけの入口にしない。
- 設定・学習元・モデル・保存先を引数で渡す。グローバル変数や関数を実行途中で差し替えない。
- 単体推論のために過去の全実験・集計・バックアップの存在を要求しない。必要なのは入力画像・選んだ重み・推論条件である。
- 移植元の記録と照合証拠は残す。旧実験全体のファイルhashへの依存と、再現に必要な入力・設定・モデルの検証を分ける。
- 新しい結果は専用の保存先に出し、固定済み研究結果を上書きしない。

## 段階ごとの到達点

|段階|作るもの|確認すること|
|---|---|---|
|1：本体と推論|Tiny U-Net、前処理、中心線・RANSAC、重み読込、`scripts/predict.py`|両学習元の保存重みが読め、同一画像の境界確率・楕円が旧実装と一致する。一様画像や不正入力も確認する|
|2：評価|固定testの読込、劣化、幾何比較器、`scripts/evaluate.py`・`report.py`|現行基本比較と、白飛びを強めた発表比較を設定で区別し、保存結果の成功数と照合する|
|3：学習|教師・損失・4ビュー／2ビュー抽選・遮蔽拡張・学習ループ、`scripts/train.py`|画像と教師、乱数列、損失、重み選択を照合する。短い動作確認の後に必要な本学習を行う|
|4：要因比較と生成|必要な外観×投影の対照、遮蔽対照、必要ならCG生成|同じ本体と設定変更で必要な研究結果を再現する|

各段階で、利用者へ配置・操作方法・確認済み動作・未実装部分を示す。主比較の最小再現に不要な診断・未採用モデルは、主実行経路へ移植しない。

## 再現の基準

最初の推論では現行のTiny U-Net16、256pxモノクロ3ch入力、確率0.5の中心線化、重み付きRANSAC、一様画像の未検出、固定OpenCV乱数を維持する。既存重みのパラメータ名と形状を維持し、1194M・多様形状を同じ入口から使えるようにする。

主比較は`output/paf_1194m_no_surface_v1/`、強化白飛びは`output/paf_whiteout_strength_3seed_v1/`が根拠。採用重みは1194M側が前者の`runs/1194m/{seed}/`、多様形状側が`output/paf_generalization_v2/runs/boundary_projection_relative/{seed}/`にある。CNNは3seed平均で、モデル統合ではない。

保存重みでの推論一致と、再学習による再現は別に検証する。GPU再学習のビット一致は保証しない。モデル・分割・劣化・評価仕様を変更する提案は、整理とは別の研究上の変更として対話で決める。Zhangの比較器を移植する場合は「Zhang 2019型（再現実装）」と表記する。正規出典はZhang, Pan, Ma, Sensors 2019, DOI `10.3390/s19235243`。

## 現在の状態と次の作業

現行ブランチは`codex/hole-region-comparison`、基準コミットは`97ae440`。現行研究コードとSYSTEM_MAP.mdはこの時点でGit追跡済み。旧SYSTEM_MAP.mdの未追跡に関する記述は、同資料の確認時点の状態である。画像・重み等のGit管理外データは別途保持する。

新ブランチ名は`codex/paf-rebuild`を予定する。現在の実行環境は元リポジトリの`.git`への書込みを許可していないため、新ブランチは未作成。新しい本体・学習・推論コードも未作成である。次の具体的作業は、利用者のローカル環境で下記を実行し、ブランチ作成後に第1段階の実装へ進むこと。

```powershell
git switch -c codex/paf-rebuild
```

新構成の独立動作、旧推論との一致、評価再現、再学習はいずれも未検証。既存研究の性能値を、新構成の検証結果として扱わない。
